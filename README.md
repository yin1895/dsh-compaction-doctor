# dsh-compaction-doctor

DSH（DeepSeek Harness）的上下文压缩插件：设置里**一个开关**，打开后它按你正在使用的模型自动校正上下文长度配置，其余全程无感。

会改配置的地方只有一种，而且只在「配置声明的能力」与「上游实际接受过的 prompt」真的矛盾时才动，改前逐字节备份。
开关关掉即完全惰性：不探测、不写配置、压缩行为与官方一致。

- 一个开关，没有按钮、没有指标、没有轮询
- 只处理**当前会话正在使用**的那一个模型，不扫描你配过的其它提供商与模型
- 懒执行：不在启动时做任何事，等你真的用到某个模型时才检查它
- 每次写配置前逐字节备份，并把备份路径写进日志
- 宿主侧可选：真实尺度重定价、分块摘要、上游报错分类

---

## 1. 它解决什么

上游模型上下文长度**配错了**是这套系统里最容易静默劣化的一类问题：配置声明的窗口、上游真正愿意接受的 prompt、以及压缩算法内部用的启发式定价三者不一致时，压缩要么不生效、要么越压越触发，而日志里通常什么也看不到。

| 症状 | 原因 | 本插件的做法 |
|---|---|---|
| 压缩几乎不生效，保留尾巴被高估数倍，可遮蔽的头部剩得很少 | 选择的单位错位：窗口总量用真实 prompt 成本计数，而候选节点用启发式定价计数，两者尺度不同 | 压缩在飞时把节点重新定价到真实尺度（`lib/rescale.js`） |
| 长会话反复触发压缩，越压越糟 | 单次可遮蔽量远小于窗口 | 真实尺度重定价 + 分块摘要 |
| 窗口配得很大时手动 `/compact` 必然失败 | 摘要输入本身超过窗口 | 分块层次摘要（`lib/engine.js`） |
| 回合直接失败，报错文案不是英文，看不出是超限 | 上游把「上下文超限」写在本地化文案里 | 分类后走一次溢出恢复（`lib/overflow.js`） |
| 配置里的窗口与上游真实能力不一致 | 配置是手写的估计值 | 比对上游目录/适配器声明与实测流量，矛盾时写回正确值（先备份） |

**只写"声明过的能力值"**：适配器或网关目录声明的值。单次会话观测到的最大 prompt 只用来**判定矛盾**，绝不作为能力值写回——观测值受采样与截断影响，不是能力。

## 2. 安装

要求：DSH desktop（或等价发行）已装好，profile 使用 `cordis.patch.yml` 分层配置。插件本身无需构建，浏览器半侧是经典脚本。

**先备份** profile 的 `cordis.patch.yml`。

### 方式 A：插件页

侧栏 **插件** → 安装 bundle → `target` 填插件目录的绝对路径。

### 方式 B：手工链接

在 profile 的 `package.json` 里加依赖并加入 bundle 列表：

```json
{
  "dependencies": { "@local/dsh-compaction-doctor": "link:/path/to/dsh-compaction-doctor" },
  "dsh": { "profile": { "bundles": ["@local/dsh-compaction-doctor"] } }
}
```

然后在 profile 目录安装依赖，并**重启 DSH**：bundle 在启动期装载，运行中的进程无法卸载它。

### 首次验证

1. 设置页左侧应出现新栏目「**上下文压缩**」（排在官方栏目之后；`settings.section` 没有图标位，导航图标由外壳按 id 兜底）。
2. 打开它，把开关打到开。
3. 回聊天窗正常用一会儿（让某个模型真的被用到），再回到设置页——状态行会说明检查结果。
4. 日志里应有插件装载行、路由注册行，以及需要修正时的 `automatic repair for <provider>/<model>: … (backup …)`。

如果栏目不出现，看 [排错](#9-排错)：最常见的原因是 patch 里缺了**裸包名**那一行（见 §6）。

## 3. 使用：只有一个开关

栏目全部内容就是三行：一句介绍、一个开关、一行状态。

```
上下文压缩

打开后，DSH 会按你用到的模型自动校正上下文长度设置，不需要你操作。

[ ●———]  已开启。已自动修正 <模型> 的长度设置（改前已备份）。
```

状态行文案由宿主给出的 `key` 在浏览器侧本地化（`locale/{zh,en}.json`），所以英文界面不会冒出中文句子。可能的取值：

| `key` | 含义 |
|---|---|
| `auto.off` | 未开启 |
| `auto.none` | 已开启，还没有用到任何模型 |
| `auto.pending` | 已开启，正在准备检查当前模型 |
| `auto.running` | 正在检查 `{model}` |
| `auto.ok` | `{model}` 的设置是正确的 |
| `auto.found` | `{model}` 的长度设置需要修正 |
| `auto.fixed` | 已自动修正 `{model}` 的长度设置（改前已备份） |
| `auto.failed` | 自动检查失败，详情见日志 |

页面只碰两个端点：`GET /state`（挂载时读一次）与 `PUT /config`（切换开关，body 只有 `{"enabled":true|false}`）。
**没有轮询、没有常驻计时器**；读不到时开关禁用并说明原因，写失败或超时后回读一次并恢复可点。

### 自动化的三条规则

1. **懒**：启动时什么都不做。开关打开后，等某个模型在一次回合里真的被用到，才去检查它；一个进程内每个 `(provider, model)` 只检查一次。
2. **只碰正在用的那一个**：只读当前路由的 provider / model，也只改那一个模型对应的配置行。其余已配置项不会被读、被定价、被改写。
3. **先备份再写**：只有当配置与上游事实矛盾时才写；写前对 `cordis.patch.yml` 做逐字节备份（文件名带插件前缀与时间戳），写后把新值记入内存，避免紧接着的复查读到旧快照而误报。

## 4. 配置

### 4.1 三行的分工

插件在 profile 补丁里插入三行：

| 行 id | 模块 | 作用 |
|---|---|---|
| `compaction-doctor-client` | 包根 | 空实现。**只为了让浏览器半侧被发现**（见 §6），无配置 |
| `compaction-doctor` | `…/probe` | 开关与诊断类字段；`Config` 标了 `.volatile()`，所以浏览器可以直接读写这一行的配置 |
| `compaction-doctor-engine` | `…/engine` | 压缩策略字段（被随包基类冻结在挂载时，改动需要一次 profile 补丁重载） |

补丁同时把随包的 `compaction-basic` 覆盖为 `disabled: true`——两个 `ctx.compaction` 注册者同时存在时谁赢不确定，**加插件和去掉插件时要把它一起加/一起删**。

### 4.2 开关类字段（probe 行）

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | `false` | 设置页那个唯一的开关。关 = 完全惰性；开 = 自动模式 |
| `autoRepair` | `true` | 自动模式的总闸。置 `false` 则只查不写（排查用） |
| `writeConfig` | `false` | 只管手动命令路径，与自动模式无关 |
| `overflowRecovery` | `true` | 是否识别上游的超限报错并恢复一次 |
| `scaleMode` | `meter` | `meter` 走随包路径但重定价；`select` 用本地选头路径；`off` 完全停用修复（A/B 用） |
| `capMaxTokens` | `65536` | 输出上限的夹取上限 |
| `maxSummaryChunks` | `8` | 分块摘要最大块数（硬上限 24） |
| `tokensPerByte` | `0.34` | 字节→token 估算系数 |
| `summaryBudgetRatio` | `0.9` | 摘要输入预算占窗口比例 |
| `selectCapRatio` | `0.85` | `select` 模式下遮蔽范围上限比例 |
| `provider` / `model` | — | 可选：覆盖路由。不填则跟随当前会话真实使用的模型 |
| `providerEntryId` | — | 可选：承载该 provider 的 profile 行 id。不填则按 provider 自动定位该行 |
| `apiKeyEnv` | — | 可选：网关密钥的环境变量名。不填用该 provider 行自己声明的 |
| `engineEntryId` | `compaction-doctor-engine` | 引擎行 id |
| `activeProbe` / `activeProbeConfirm` | `false` | 真实边界探测（**消耗额度**），两个都要开 |
| `probeOnStart` | 忽略 | 历史字段，保留只为兼容既有 profile 补丁 |

**优先级**：`默认值 < 引擎行 config < probe 行 config`，开关值（存在插件自己的状态文件里）位于最上层——用户点的那一下永远胜出。

### 4.3 开关存在哪里

`<profile>/compaction-doctor.state.json`，**插件自己的文件**，不写 profile 补丁。原因：

1. 插件那几行是 **bundle 补丁插进来的**，profile 文件里没有这些行；要在 profile 里覆盖，必须重写一条相同 `id` 的行，而 **`name` 是断言**——名字不匹配，整行会被跳过。
2. 补丁按行**整体替换 `config`**（从不深合并），只写一个键会把这一行的其它字段一起抹掉。
3. 写 profile 补丁要等**补丁重载**才生效，而重载是异步的：刚写完立刻回读会读到旧值。

改成插件自己的文件后，`enabled` **先在内存生效**（`GET /state` 和引擎的下一次读取立刻看到新值），再落盘（下次启动恢复）。落盘失败不影响本次会话，只在日志里记一句。

> **改完插件文件必须重启 DSH。** 宿主半侧只在 DSH 启动时被加载一次；补丁重载只对 profile 补丁生效，不会重新加载插件代码。
> 覆盖文件后只刷新页面会造成「新版页面 + 旧版宿主」的错配。新版页面会把这个状态直接说出来并提示重启。

## 5. 与设置页的接口

页面不靠猜：宿主暴露一组固定端点，实现见 `lib/status.js`。

| 端点 | 作用 | 谁在用 |
|---|---|---|
| `GET /state` | 开关值 + 状态行所需的 `key`/参数 + 诊断明细 | 设置页挂载时读一次 |
| `PUT /config` | 写开关，body 只有 `{"enabled":true\|false}` | 设置页的开关 |
| `POST /diagnose` | 手动诊断（只读） | 命令与排查 |
| `POST /apply` | 手动写回，需 `confirm:true`，先备份 | 手动路径 |
| `GET /backups` · `POST /restore` | 备份列表与还原，还原需 `confirm:true` | 手动路径 |

**鉴权**：宿主 web 服务本身零鉴权，其 `/api` 信任栅栏也不覆盖自定义前缀，所以每个请求都要过三道闸：
① 必带自定义请求头（跨站简单请求伪造不出来，会触发预检）；② 若有 `Sec-Fetch-Site` 必须是 `same-origin`；③ 若有 `Origin` 必须与 `Host` 同源。写操作另要求 `Content-Type: application/json`。

## 6. 插件开发要点

写带浏览器半侧（设置页 / 客户端扩展）的 DSH 插件时，这三条最容易踩：

1. **patch 里必须有一行 `name` 是裸包名。** 客户端模块装载器把 Loader 行映射到包时，用的是「精确包名」判定——**带子路径的 specifier 直接返回 `undefined`**（`dsh-client-modules` 的 `exactPackageSpecifier()`），于是 `pkg/subpath` 这类行永远不会让这个包被注册成浏览器模块：`/plugins/<包名>/client.js` 返回 404，宿主侧却一切正常，极易误判成「没装好」。所以 patch 里要额外有一行 `name: '<包名>'`，它的模块**不要导出 `default`**，免得把服务二次实例化。
2. **参与 waterfall 的监听器必须调用 `next()`。** waterfall 会**截断**整条链：不调用 `next()` 的监听器不仅拦截内置行为，它的返回值还会变成整个 waterfall 的结果，消费者读到 `undefined` 后当场失败。兜底注册之类的副作用请放在别的 hook。
3. **宿主半侧只在启动时加载。** 改完插件代码要重启宿主进程；只刷新页面（改的只是浏览器半侧）会造成版本错配。

浏览器半侧的约定：经典脚本、调用一次模块装载器的 `load({ id, factory })`、`id` 等于包名、不出现顶层 ESM 语法、`require` 只用平台提供的种子模块、样式表用带标记的 `<style>` 去重以便卸载时回收。

## 7. 形式化验证

这个插件的开关链路（宿主写路径、存储、浏览器状态机）有一份形式化规格与一份穷尽检验器，因为「开关点了没反应」这类故障靠多试几次是查不出来的：

- [`docs/formal.md`](docs/formal.md) —— 状态机模型、事件字母表、11 条不变量与逐条证明，以及每个线上故障对应违反了哪条不变量。
- `test/model/check.mjs` —— 按规格第 6 节做**穷尽**检验：在虚拟时钟里驱动真实浏览器半侧代码、直接调用真实宿主函数、按抽象状态去重做状态图 BFS，并在系统调用点做故障注入。发现反例时以非零退出码结束。

它带来的第一类产物是**规格修正**（例如「读失败因此不显示值」到底算不算说谎），第二类是**实现修正**（例如层级配置合并用对象展开而不是格并，缺键会把下层值抹掉）。检验器的判定必须在运行期从当前源码推出，不能写死行号——否则改好代码反而会失败。

## 8. 开发与测试

```bash
node test/nm/run.mjs        # 宿主半侧
node test/client/run.mjs    # 浏览器半侧
node test/model/check.mjs   # 形式化穷尽检验器
# 或
npm run test:all
```

三套件全部离线可跑，不需要网络、不需要装依赖（宿主测试用桩模块，检验器用临时目录装载真实签名）。**套件全程沙箱化**：`$DSH_HOME` 指向临时目录并有断言兜底——开关是一条真实的写入路径，测试绝不能写到跑它的那台机器上。覆盖范围：

- **宿主**：预算与选择算法、配对裁剪、分块摘要、重定价、溢出分类、手动命令报告、配置写入的三条路径（编辑器优先 / 文件回退 / 开关状态文件）、以及事件契约回归（waterfall 必须转发、监听器形参个数、行 `Config` 必须有 `.volatile()` 字段才成为可配命名空间）。
- **浏览器半侧**：模块格式契约、注册项、请求路径集合、样式去重、locale 键集一一对应、单个可交互控件、无轮询、失败恢复、旧宿主识别。
- **形式化**：见 §7。

### 项目结构

```
lib/
  index.js     包根：只为了让浏览器半侧被发现（空实现，无 default 导出）
  probe.js     宿主：诊断/修复/状态能力、开关、手动命令、行 Config
  engine.js    宿主：压缩引擎实现（重定价 + 分块摘要）
  status.js    宿主：设置页 HTTP 通道（三道闸 + 端点分发 + YAML 行改写）
  rescale.js   宿主：真实尺度重定价（可重入、冻结、保留原值）
  overflow.js  宿主：上游报错分类
  plan.js      宿主：预算与选择算法
  util.js      宿主：工具
  client.js    浏览器半侧：设置页栏目
locale/        zh/en 文案
cordis.patch.yml  插件补丁（停用随包 compaction 行，插入本插件三行）
docs/formal.md    形式化规格
test/          三套件
```

## 9. 排错

| 现象 | 原因 | 处理 |
|---|---|---|
| 设置页里没有这个栏目 | patch 缺裸包名那一行（§6），或安装后没重启 | 检查 profile 补丁里是否有 `name: '<包名>'` 的行，然后重启宿主 |
| 栏目在，但开关点了没用 / 一直不可点 | 页面已更新而宿主半侧还是旧版（宿主只在启动时加载） | 重启宿主；新版页面会直接提示这一点 |
| 状态行说读不到设置 | 宿主端点未注册，或请求被闸门拦下 | 确认宿主侧插件行已加载（日志里有装载与路由注册行） |
| 自动修正没发生 | 开关未开、`autoRepair: false`，或该模型还没被真正用到 | 先正常用一轮该模型，再看日志 |
| 想确认某次修正改了什么 | 每次写入都留了逐字节备份 | 看日志里的 `backup` 路径，文件名带插件前缀与时间戳 |
| 压缩行为看起来没变化 | `scaleMode: off`，或探到配置本来就是对的 | 检查该行配置；`off` 是完全停用修复的档位 |

## 10. 回滚

1. 从 profile 的 bundle 列表移除本插件、删除依赖，重新安装依赖。
2. 删掉 profile 补丁里本插件的三行 `insert`，**以及** `compaction-basic` 的 `disabled: true` 覆盖行（必须一起删，否则两个压缩注册者同时存在）。
3. 或直接用备份整体还原（把最新那份备份复制回 `cordis.patch.yml`）。
4. 重启 DSH。

## 11. 已知限制

- **栏目图标由外壳决定**：注册项只有 `id`/`order`/`label`，导航图标按 id 白名单兜底，本插件不为此做 DOM 补丁。
- **策略字段需要一次补丁重载**：被冻结在挂载时的字段改动不会纯内存生效。
- **`select` 是备用路径**：任何一步拿不准都回落到随包路径，宁可什么都不做也不猜。
- **真实边界探测消耗额度**：默认关闭，需两个开关同时打开。
- **观测值永远不作为能力值写回**：只用于判定配置与流量是否矛盾。

## 12. 兼容性

对上随发行版安装的包只声明可选的 peer 依赖，靠安装目录的模块解析共享同一份实例（所以 `super()`、`instanceof`、服务品牌都成立），不在 profile 里重复安装。
真正的门控是 `engines.node` 与 peer 约束；`package.json` 里的 `dsh.compatibility` 仅供参考，运行时并不读它。
